## 玩家问题与已有能力

### 玩家问题
1. 作者在修改故事对白后，无法调整地图上的房间格局、墙体通道、怪物站位或出生点位置；
2. 手动在文本中数行列字符容易导致地图宽度不一致、坐标越界或将营火放在墙体上的致命错误；
3. 编辑过程中缺少撤销/恢复和可达性校验，容易意外造成剧情关键目标被墙壁永久封死。

## 复现 / 目标场景

在隔离 Docker 环境中：
1. 作者打开 T15a 中克隆出的样板草稿地图（固定 25×15 尺寸）；
2. 切换为格子编辑模式：修改一段墙体（`#`）为地板（`.`），并移动门（`D`）的位置；
3. 将守卫怪物与 NPC 点选放置到新坐标；
4. 调整出生点 `playerStart` 与西岸营火 `campfire` 坐标；
5. 系统自动校验：若作者误将营火放于墙体内，即时给出明确错误提示与高亮标记，阻止保存发布；
6. 校验通过后点击“试玩”，服务端以 `isPlaytest: true` 启动测试局，在该定制地图中正常移动、开门并完成剧情结局；
7. 退出试玩平滑返回编辑器，原有草稿修改完好保存。

## 范围与实现约定

1. **固定样板尺寸与横向桌面视口**：
   - 首版固定编辑 25×15 样板地图，不引入动态扩缩尺寸（避免复杂的网格裁剪与悬空实体搬迁）；
   - 编辑器核心面向横向桌面视口（1280×800 以上），保留既有手机端布局回归，不新增手机端微操优化要求；
   - 瓦片类型：墙（`#`）、地板（`.`）、门（`D`）；
   - 提供撤销（Undo）、重做（Redo）与未保存离开拦截。
2. **实体放置与场景稳定 ID 绑定**：
   - 允许放置/移动：已有 NPC、现有怪物种类（`bandit`, `goblin` 等）、箱子、营火、楼梯；
   - 实体与场景通过稳定实体 ID（`scene.npcId`, `scene.doorId`）关联，移动坐标不破坏场景绑定；
   - 若作者尝试删除已有剧情场景引用的 NPC 或门，弹出依赖警示，严禁产生悬空引用。
3. **保守可达性与合规校验**：
   - 出生点 `playerStart` 与胜利营火 `campfire` 绝不可处于墙体上或超出地图边界；
   - 基础连通性检查：若核心目标（如营火、关键 NPC）被无门实心墙完全闭合封死，标记错误；
   - **保守原则**：对需要钥匙或剧情检定才能打开的门，不采用简单的洪水填充误判，而是明确提示需作者通过试玩验证。
4. **草稿错误容忍与试玩闭环**：
   - 允许保存包含可达性或坐标错误的草稿；错误状态阻止安装、发布导出与进入试玩；
   - 试玩由服务端打上 `isPlaytest: true` 标记，结算跳过正式英雄写回，刷新平滑返回编辑器，仅清理该草稿对应的临时存档。
