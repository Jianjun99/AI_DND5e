# T6 — 一个有记忆与后果的 AI 遭遇

- 状态：done
- 更新：2026-10-03
- 前置：T2–T4、T8。
- 类型：小规模玩法验证；不以生成大量内容为目标。

## 玩家目标

用角色能力做选择，之后能看到不同后果；NPC 或同伴记得一件真实发生的事。当前同伴任务主要是忠诚门槛与杀怪计数，未匹配的自由输入只产生旁白。

## 代码入口

- `server/game/engine.js` 的 skillCheck、交互、奖励与同伴状态。
- `server/game/companions.js`、campaign.js；game/city 的快照与结算。
- `server/game/dm.js`、retrieval.js、referee.js。
- `server/game/content.js`、一个现有 content pack；T8 内容检查。
- 对话/任务面板及 T4 guidance。

## 第一版范围

选一个小遭遇，例如守卫阻挡遗迹入口：战斗可通过；持有已找到的凭证也可说服；角色能力可作为可选检定，但不必增加第三条路线。

1. 内容用最小 JSON 描述 scene、choice、condition、effect；复用现有引擎判定与资源，不运行内容包提供的任意 JS。
2. 至少两个真实可执行解法，有不同的事实或 NPC 后续回应；失败仍有可继续路径。
3. 引擎写结构化事实，随存档/档案正确持久化；AI 总结不能成为新事实。
4. 一个 NPC/同伴在下次交谈或回城时引用真实选择，固定文案也能表达记忆。
5. AI 在合法选项与已确认事实范围内解释选择、写对话，不授予奖励、决定 DC 或掷骰。
6. 内容定义的相关引用、条件和后果由 T8 的检查机制验证；格式同步 MODDING。

自由输入可以先使用现有明确动作/按钮。通用 AI 意图解析、开放环境组合与长篇记忆另立任务。不要为单个遭遇先实现完整剧情语言或阵营模拟。

## 验收标准

- [x] 两种解法均可完成，有实际不同后果而非只换文案。
- [x] 刷新、结束冒险、回城后事实保留，NPC 的反应与事实一致。
- [x] 奖励与一次性事实更新不重复；对已过期选项重新校验。
- [x] 无 LLM、超时、无效模型文本时选择与判定仍完整可用。
- [x] 模型无法通过对话直接改变奖励、HP、检定或故事事实。
- [x] 老模组与原主线继续可玩；扩展协议有完整、可加载示例。

## 验证

分支行为、失败继续、事实持久化、重复选择、内容错误、mock LLM 的越界输出均验证。真实浏览器分别走两条路线；完整 verify。新增战斗/奖励数值则 balance-sim 并报告变化。

## 试玩步骤

1. 用当前代码重新启动游戏服务以加载新内容；如果游戏本身也部署在 Docker，需重新构建游戏镜像再启动，单纯重启旧镜像不会加载改动。在首页选一个英雄，进入城镇的区域地图，点击“山谷哨门”（等级 1–3，自由冒险）。准备页也能选择该地图。
2. 建议先选普通难度、单人。走到旧木箱旁 `(3,3)`，点击 `(3,4)` 的箱子取得山谷通行印，再走到守门人身边 `(5,3)`。点击右侧“查看遭遇选项”，或和守门人互动。
3. 和平路线：选择“交回通行印，和平通过”。印章消耗一次，守卫离开，没有战斗 XP/掉落。面板立即显示伊凡记住了什么。
4. 战斗路线：可跳过箱子，直接在守门人身边选择“选择交战，用武力通过”。使用现有攻击/法术/结束回合按钮战斗。完成后守门人表达戒备，奖励按原战斗规则结算。失败复活后可改走和平路线。
5. 门开后走到 `(11,3)`，点击 `(12,3)` 的圣物；走回 `(1,3)` 营火，等待结算成功再回城。再进入山谷哨门，“听听守门人记得什么”/遭遇面板或 NPC 对话会引用上一次真实选择；新的冒险仍可作不同选择。

这个例子没有依赖真实 AI；开启 AI 后对话仅增加表达。没有加入自由输入意图解析、通用剧情语言或全 NPC 长篇记忆。旧存档地图快照不重写，试玩请新开山谷哨门。
