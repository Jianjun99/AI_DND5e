# 1.11.0 候选版本交接手册 (NEXT_VERSION_1.11_HANDOFF.md)

本文件是 1.11.0 候选版本开发的全局交接手册。当前基线版本为 1.10.0；开发过程中不修改 package.json 版本号、不提交、不推送、不发布。

---

## 一、版本核心目标

打造一套新手友好的单人 D&D 2024 入门冒险体系：
1. **双章完整样板**：以现有「渡口的失踪信使」（第一章）为基础，扩充第二章「河湾哨所的决断」，承接第一章 reported / protected / accord 三种结局并体现至少两处玩法差异（通行方式、物资帮助、DC 降低），最后达成三大收束终局（`lawful_order`, `free_haven`, `shared_covenant`）；
2. **零资源保底推进**：在 0 GP、0 药水、0 法术位且检定全失败时，依然具备确定的推进路线，不因检定预检锁定剧情；
3. **有限自然语言行动**（T13a）：覆盖调查、交谈、使用道具、场景选项、基础攻击五大类，确定性词典优先，可选模型提案，服务端权威重验；
4. **创作者闭环**（T15a / T15b）：支持作者一键克隆样板、可视化编辑 NPC 与剧情选项、编辑 25×15 基础格子地图，通过 T8 校验导出/导入独立内容包，且试玩与正式存档完全受控隔离。

详细样板剧情与逐场景文案规格见：[`docs/SAMPLE_ADVENTURE_1.11.md`](SAMPLE_ADVENTURE_1.11.md)。

## 二、架构契约与设计规范摘要

### 2.1 跨章历史引用契约
- **载体**：`char.encounterFacts` 与 `char.settlements`；
- **资格算法**：前章终局事实必须在 `char.settlements` 中存在对应来源局收据，且收据的 `mode` 必须严格为 `'victory'`。若来源局因撤退（`retreat`）或死亡（`over`）结算，严格判定为未完成；
- **确定性排序**：优先按收据结算时间戳 `completedTs` 降序排序，时间并列时按事实 ID 字典序打破并列；
- **局内冻结**：在 `POST /api/game/start` 时由服务端选定并冻结至 `state.historyBinding`，刷新与读档不重新计算，跨英雄绝对隔离，不自动推进第二章场景；
- **选项条件**：仅扩充纯数据标量条件 `{ "type": "history_ending", "ending": "..." }`，由 T8 校验器校验目标故事与终局真实存在，杜绝任意脚本。

### 2.2 动作路由与提案 DTO
- **动作路由**：`POST /api/game/:id/action`，判别字段固定为 **`type`**（如 `type: 'sceneChoice'`）；
- **提案 DTO 隔离**：模型提案对象为中间 DTO，在提交前转换为标准动作载荷，服务端在获取互斥锁后于最新快照上权威重验；
- **单步原则**：单次输入在机械上至多执行一个核心动作，不可逆或金币消耗操作前弹出确认。

### 2.3 样板克隆与安全试玩
- **重映射范围**：新包命名域 `custom_<slug>`；递归成对替换内部地图 ID、两章故事 ID、门禁、场景与包自有道具 `courier_ledger`；明确保留语义 ID `campfire`、`player` 与全局规则表（`potion_healing`, `bandit`）；
- **草稿错误容忍**：草稿允许带校验错误保存，错误状态明确拦截安装、导出与试玩；
- **草稿路径与身份**：`draftFileFor()` 是唯一的草稿路径入口，ID 先过 `[a-z0-9_-]+` 文法再确认
  `resolve` 后仍在 `data/drafts` 根内；文件名是身份，`pack.id` 不一致一律 409 `draft-id-mismatch`，
  导出/安装/试玩随之拒绝；内容容错不等于任意路径可写；
- **服务端试玩受控**：试玩身份由服务端铸造（专用试玩英雄 `playtestHeroId(draftId)`，携带
  `isPlaytest`/`ownerDraftId`），客户端自称无效；草稿内容以快照随存档走，绝不写共享注册表；
  结算只接受"真实结束 + 属于本草稿"的运行，收据落在草稿英雄上，正式英雄字节不变；
  退出/刷新/重复退出/删除草稿/服务重启均有确定行为，清理只按资源自身字段而不按前缀批量删档。

## 四、验证约束与保全规则

1. **Docker 完整验证**：
   - 每次代码改动收尾必须运行 `npm run verify`；
   - 固定 2 CPU / 4 GiB 内存，容器名 `ai-dnd-verify` 互斥；
   - 必须具备完整 Linux Chromium 与 WebGL2 环境，禁止假称自动降级而跳过环境检查；
   - 若改动战斗或规则数值，同容器追加 `--balance-runs=50` 并在报告中对比胜率。
2. **快速开发检查**：
   - 迭代过程中可使用 `npm run check` 或 `npm run check -- --browsers=<id>` 获取 fail-fast 信号。
3. **保全底线**：
   - 严禁 `git reset --hard`、`git clean` 或删除未跟踪文件；
   - 严禁修改玩家正式 `data/` 目录或生产卷；
   - 严禁主动 commit / push / 改版本 / 打 tag / 发版。
