# 怎么把项目交给下一位 agent

这份指南给项目拥有者。你无需转述整段聊天或自己解释代码；让下一位 agent 打开仓库，按入口与单项任务工作即可。

## 当前自动验证规则（优先于下方历史提示）

在仓库根目录执行 `npm run verify`。入口自动构建独立 `Dockerfile.test`，完整验证、服务端和 Chromium
都在专用 Docker Desktop Linux 容器里，固定 2 CPU / 4 GiB RAM。所有 agent 共享容器名
`ai-dnd-verify` 原子锁；第二轮返回 73，等前一轮结束，不删其他 agent 的容器，不换名称绕过。
容器使用独立测试数据，关闭真实 AI 和外网；只挂载日志，不挂载玩家存档/模型配置/生产卷。
成功、失败、超时均清理本轮容器，产物在 `artifacts/verify/`，以真实退出码报告。
缺 Chromium/WebGL2 或磁盘检查文件必须失败；不能跳过后报全绿。遇到 Windows 问题先报告，
不自行回退宿主机起浏览器。MCP `run_verify` / `run_replay` / `run_balance_sim`、CI 和人工入口一致；
回放与数值模拟在完整 verify 后按需追加，命令参数见测试指南。
完整说明见 [Docker 测试指南](DOCKER_TESTING.md)。下方历史 DATA_DIR/本机 Edge 操作不再用于自动验证。

**当前进度（2026-10-03）：T5a/T7a 已关闭；T8 与用户授权续做的 T6 均完成，最终 Docker 验证 27 套件、smoke/balance 全绿，容器清理完成。**
环境与证据见 [环境任务](../tasks/docker-test-environment.md)、[T8 结果](../tasks/t8-content-validation.md)和[T6 结果与试玩步骤](../tasks/t6-remembered-encounter.md)。山谷哨门两路线各 50 次模拟，和平完成 100% / 战斗 96%。本轮队列无未完成项；下一位 agent 先读取上述结果和 MODDING 的 scene 协议，再按玩家试玩反馈领取新任务，不从零重写 T6/T8，也不把旧提示词当作待执行任务。
[独立复核报告](T5A_T7A_REVIEW_2026-10-02.md) 和下方 T7a 提示保留为历史，不重开已完成任务。

## 第一步：让它看到同一份文件

在下一位 agent 的工具里打开项目目录。本机是 `G:\ai_DND`，不要只把报告截图发给它。它需要能读取源代码、编辑文件并运行命令。

如果仍使用这个目录，本轮的入口与任务规格已经在里面。换电脑或使用只读取 GitHub 的 agent 时，需要把这些新文档和当前代码一起交过去；未提交的新文件不会自动出现在远程仓库。提交/上传由你另行授权，本次没有操作。

玩家数据在 `data/`，与代码分开。开发测试使用独立数据目录，不需要把真实模型配置或玩家存档作为任务上下文。

## 第三步：你怎样验收

让 agent 给出的报告至少回答：

1. 玩家感知到什么变化，改了哪些文件？
2. task 的验收标准逐项是否完成？
3. `npm run verify` 是否完成、是否全部通过？客户端在哪个真实浏览器查看？
4. 有没有存档/接口变化；如有，旧档怎样保持可用？数值变化有没有 balance-sim？
5. 你从哪个页面开始、点什么、应该看到什么？还有什么未完成？

T1 你可以这样试玩：用测试英雄打开准备页，选丘陵、困难、独行，出发后看地点/难度/队友；再选一位非默认队友。再从区域地图出发一次。agent 应准备好测试环境并给你实际可访问的地址和步骤。

其他任务的试玩路径写在各规格里。测试全绿仍要看玩家行为是否达到目标，尤其 T4/T5/T6。

## 中途换 agent 或上一个任务没做完

要求正在工作的 agent 先把对应 task 的“交接结果”更新：已改文件、已完成标准、未运行/失败的检查、目前阻碍、下一具体步骤。未完成时保持 in_progress，勿写 done。

接着发：

```text
请接手 G:\ai_DND，按 START_HERE.md 阅读资料。
继续 tasks/<实际任务文件>.md 里未完成的工作。
先检查 git status/diff 和 task 的交接结果，保留上一个 agent 的修改。
重新确认已完成/未完成部分，不从零重写；完成剩余验收与完整 verify。
更新任务状态并报告结果，不主动 commit/push/发版。
```

若缺少临时环境，让它根据规格重新建立独立测试环境；交接不能依赖某个临时进程一直活着。

## 不确定实现是否可靠时

可另请一位 agent 只审查，不修改：

```text
请在 G:\ai_DND 按 START_HERE.md 了解项目。
只审查 tasks/<实际任务文件>.md 对应改动及当前 git diff，暂不修改代码。
核对玩家验收、状态/存档、接口、断开或慢 AI、重复操作和测试覆盖。
报告能复现的问题、文件位置和影响；检查实际 verify 结果。
若需运行复现，使用独立 DATA_DIR，不使用真实玩家模型设置。
```

你只需要决定下一项优先级、按给定路径试玩、授权必要的产品范围变化和发布。文件定位、实现方案、测试环境、修复和文档同步是开发 agent 的工作。
